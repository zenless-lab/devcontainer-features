# AGENTS.md

## Project Context

This repository contains reusable Dev Container Features.

- `src/` stores feature implementations.
- `test/` stores feature test scenarios and verification scripts.
- `.github/workflows/` stores CI workflows for validation, testing, publishing, and secret scanning.

## Repository Structure

Use the repository structure as the primary source of truth.

### Feature Layout

Each feature lives in `src/<feature>/`.

Typical files:

- `devcontainer-feature.json`: feature metadata, options, and versioning.
- `install.sh`: installation and configuration logic.
- `README.md`: generated or user-facing feature documentation.
- `NOTE.md`: supplemental notes when extra context is needed.

### Test Layout

Each feature usually has a matching `test/<feature>/` directory.

Typical files:

- `scenarios.json`: scenario matrix for the feature.
- `test.sh`: main test entrypoint.
- Additional shell scripts: scenario-specific assertions or setup.

## Working Rules

- Prioritize using English for code, documentation, and comments.
- Keep changes focused and minimal.
- Do not add feature-specific guidance here unless it is broadly reusable across the repository.
- Preserve existing file naming and directory conventions.

## Setup

This repository does not have a single build step for all features.

Common setup for local validation:

```sh
npm install -g @devcontainers/cli
```

## Validation And Testing

When changing a feature, prefer validating only the affected area.

Autogenerated tests for one feature against a base image:

```sh
devcontainer features test --skip-scenarios -f <feature> -i mcr.microsoft.com/devcontainers/base:ubuntu .
```

Scenario tests for one feature:

```sh
devcontainer features test -f <feature> --skip-autogenerated --skip-duplicated .
```

If your change affects multiple features or shared behavior, run the relevant commands for each affected feature.

## Editing Guidance

- Update `devcontainer-feature.json` and `install.sh` together when feature behavior changes.
- Keep `README.md` aligned with the current feature options and behavior.
- Put feature-specific test coverage in the matching directory under `test/`.
- Avoid broad refactors unless they are required by the task.

## Git Conventions

Use Conventional Commits.

- Prefer commits without a scope.
- Examples: `feat: add uv completion setup`, `fix: handle missing package manager`.

## Pull Request Expectations

- Explain what changed and why.
- Mention which feature directories were affected.
- Mention which validation or test commands were run.
